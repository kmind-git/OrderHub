## 首期输入范围

本地闭环只接收 `AAPL.GOX` 的 USD 股票、整股、常规时段、`LIMIT + DAY`
买单及卖出**已确认归属持仓**。数量为正整数股；价格和费用使用精确十进制，
必须符合当前合约 `price_increment`、`size_increment` 和精度。当前节点的
`AAPL.GOX` 测试合约配置 `price_increment=0.01`、`price_precision=2`；
这仅是本地 fixture，不代表所有美股或实际券商的 tick 规则。
`MARKET`、GTC/IOC/FOK、碎股、卖空、融资、ETF、盘前盘后、
`post_only`、`reduce_only` 均不在首期可受理集合。客户端请求这些组合时
在持久受理前返回稳定的 `UNSUPPORTED_CAPABILITY`，不能静默改成 DAY、
丢掉 flag 或交给模拟器决定。未来扩展须有通道能力、资产计算规则、日历和
风控验收。撤单保留独立授权/持久化路径，不因新单门禁自动关闭。

| 输入          | 必须带的版本和来源                                                                                    | 使用规则                                                                                                   |
| ------------- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 合约定义      | `instrument_id`、交易场所/路由、币种、价格与数量增量、精度、交易状态、`instrument_revision`、生效时间 | 版本变化重新验证未发订单；缺失或未知状态不放行新风险。不能只按股票代码匹配真实券商合约。                   |
| 报价/盘口     | 来源 ID、合约、源事件时间、接收时间、该来源内序号/快照版本、买卖价量、完整性标志                      | 精确解析且匹配当前合约；旧帧/非法帧不回退最后合法报价。完整顶层替换可跨缺口，报价停更不阻断新单。          |
| 交易状态/日历 | 状态版本、来源和时间；明确常规时段、暂停/恢复                                                         | 状态未知、停牌、非授权时段拒绝新单；不能用固定 UTC 时刻代替交易日历与夏令时。                              |
| 账户/持仓     | 账户 ID、来源、快照版本/覆盖范围、源时间和接收时间、币种、余额/购买力及可归属持仓                     | 账户事实和策略归属分开保存；缺快照或覆盖不足保守阻断。成交后由已提交回报更新本地账本，仍要与外部事实对账。 |

时间比较使用**正常运行时持续推进的时钟**；确定性测试注入可控时钟。
源时间不能晚于接收时间，接收时间不能晚于当前时间。非报价输入保留 500 ms
源到接收上限及交易状态 5 秒、账户/持仓 10 秒的年龄上限；失效后需要完整快照，
不能只更新本地时间戳。未知交易状态、停牌、元数据冲突和整体输入断开仍阻断新单。

2026-10-11 的 `local-usd-v2` 修订覆盖原
[阈值 v2](../../audit/orderhub-simplification-2026-09-29/run-05/thresholds-v2.md)中的报价门禁：
报价不设年龄或源到接收延迟上限；仅报价断流、缺口、旧帧或非法帧不阻断新单。
启动仍需合法报价，定义变化后需匹配修订的报价。报价只供估值/敞口等原有计算，
不再限制订单相对报价的价格偏离；订单原限价保留。
仅报价重连重置报价输入代和序号基线，旧代排队帧丢弃，首帧为完整快照；
账户/状态继续有效。共享 JSONL EOF 或无法识别类型的损坏帧仍属于整体输入故障。
估值沿用最后合法报价及其真实时间/来源，`writable/stale` 不保证报价实时。

## 当前本地模拟器的接口边界

2026-09-30 读取外部 `rust-trader` 源码版本
`5940c0e9e2fdc962b5b731814491c58694d1e1cd`，包版本 `0.1.1`。
该项目不在本仓库，本次没有修改或启动它；以下是**源码能力核对**，
不是运行时兼容性认证。

| 接口                           | 已见字段/行为                                                                             | 对 OrderHub 的结论                                                                                                 |
| ------------------------------ | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| FIX 4.2 `35=D/F`、`35=8`       | 支持限价/市价、仅 DAY、撤单及 New/部分成交/成交/取消/拒绝回报。                           | 用于 P6 本地订单闭环；当前 OrderHub FIX client/ExecutionClient 已接线，但边界回归仍须运行。                        |
| REST `GET /api/instruments[/]` | 返回品种符号列表；没有币种、tick、交易状态或修订号。                                      | 只能用于发现/诊断，不能代替合约权威定义。                                                                          |
| REST `GET /api/book/{symbol}`  | 盘口档位的 `price`/`quantity` 为 JSON `f64`，带 `sequence`；无源时间/心跳。               | 只作可观测性和对账辅助；不得把浮点档位转换回“精确”价格用于准入、现金或成交账本。无变化时也不能据请求时间判定新鲜。 |
| REST `GET /api/stats/{symbol}` | 报价/成交统计同为 `f64`，无精确源时间。                                                   | 不作估值或交易状态的权威输入。                                                                                     |
| REST `GET /api/sessions`       | 会话 ID 列表，不是账户状态。                                                              | 不能证明订单、成交、持仓或账户已对账。                                                                             |
| 订单/成交/持仓/账户查询        | 当前 REST 路由未提供，OrderHub 本地 client 的 `query_order`、`query_account` 返回不支持。 | 恢复后有未决或未知发送订单时保持 HALTED；自动对账转 READY 需外部接口版本和覆盖测试。                               |

模拟器内部 `InstrumentSnapshot` 有 `published_at`，但 REST DTO 没有暴露；
不能据内部字段推断 HTTP 客户端收到源时间。当前 `configs/instruments.txt`
也只有数字 ID 和符号，没有 tick、币种或交易状态。

## P4/P6 输入实现与外部阻塞

P4 在本仓库提供有界的 Rust 行情/账户输入接口和确定性 fixture，使用
十进制字符串、显式事件时间/序号、合约修订和可控测试时钟。fixture 是
**本地测试事实**，不得包装为来自券商或模拟器 REST 的账户事实。P6 可用
真实模拟器 FIX socket 验证提交、撤单、回报和重连；缺订单/成交查询时，
只声明受限的首次进程闭环，不启用自动恢复交易。重启后若外部事实覆盖不足，
保持 HALTED 并列出缺失证据，不能仅靠本地日志进入 READY。

自动恢复交易需要模拟器或目标执行通道提供：按稳定订单 ID 查询当前与
必要终态订单、按时间/序号分页查询成交及修正、账户与持仓完整快照、
窗口覆盖水位和身份/会话语义；还须验证断线重放与重复回报。精确实时
行情若继续来自模拟器，则需版本化十进制报价、源时间/心跳和交易状态。
这些是外部接口需求，不以猜测其已存在代替验收。
