# P4 行情与账户输入实现

实现位于 `crates/orderhub-gateway/src/inputs.rs`，契约见
[行情与账户输入](market-and-account-input.md)。验收用例位于
`crates/orderhub-gateway/tests/p4_inputs.rs`；验收状态以实际运行记录为准。

2026-10-11 规则修订：当前使用 `local-usd-v2`，已移除价格带及报价新鲜度门禁。
原 P4 记录保留原规则的证据范围；当前规则见下文和主方案的业务规则修订。

## 输入路径

```text
本地可信适配器 → InputSender（有界队列）→ 核心线程 InputRuntime
    → Cache / Portfolio
    → OrderHubBridge 的新增风险门禁 → 原生 RiskEngine
```

`InputRuntime::channel` 配置来源 ID、策略白名单和队列容量；默认输入队列
1,024 条，可选范围 1–4,096。输入通道与订单/撤单请求通道分离，输入拥塞不会
占用订单/撤单接入队列。P5 已将新单、撤单、查询拆为 1,024/128/128 条独立
有界队列；执行回报队列为 1,024 条，见 [业务运行时](business-runtime.md)。

核心线程注册实时定时事件发送端，以 4,096 条有界队列收取原生实时钟回调，
并在回调所属的核心线程分发。定时队列满或停止时将生命周期门禁置为 HALTED；
节点使用能取得该发送端的 `LiveClock::default()`，原生定时任务由 common 的
实时运行时驱动。完整生命周期与恢复重构仍在 P6；本阶段新单许可同时看
`GetState.writable`，不能只根据原型的 `readiness` 字段判断所有恢复条件已满足。

每次核心循环最多消费一个队列容量的输入；适配器不访问 `Rc<RefCell<Cache>>`。
报价只更新内存 Cache/Portfolio，不提交 redb，不生成持久事件或恢复增量。
合约、账户和交易状态继续进入业务日志；报价更新不推进业务游标。
入队前限制字段长度和归属条目数。已识别的非法报价或报价入队失败会丢弃并记录，
不使账户/状态失效。`InputSender::invalidate_quotes` 表达仅报价连接丢失：保留
最后合法报价，重置报价序号基线；重连首帧须为完整快照，旧报价代的排队帧被丢弃。
其他必需输入入队失败、未知类型解码失败或整体连接中断会改变全流输入代号；
旧代号排队数据不能重新打开门禁。整体来源重连须重新提交所有流的完整快照，
非报价流序号继续递增。

本期范围固定为 `AAPL.GOX`、USD 现金账户 `GOX-001`、整股、`LIMIT + DAY`。
合约精度与 tick 来自版本化定义，初始测试 tick 为 `0.01`。来源不在本期范围的
合约、路由、账户或归属不会进入内核。策略白名单在节点中为 `ORDERHUB-S001`；
增加账户、合约和策略配置由后续能力扩展承接。

## JSONL 本地入口

设置 `ORDERHUB_INPUT_STDIN=1` 后，节点用独立线程从标准输入读取连续 JSONL。
本入口来源 ID 固定为 `local-fixture-v1`，明确代表**本地 fixture 事实**。
没有配置输入源时，节点不再创建假定的百万美元账户或硬编码合约；新单保持阻断。
输入流 EOF 或最后一个发送端退出视为断连。

每行最大 16 KiB，字段详见 `InputEvent`。以下规则适用于四类事件：

- `instrument`：完整合约定义、修订号、生效时间、币种与增量/精度。
- `quote`：完整顶层买卖价量；`snapshot=true` 是重同步快照，`false` 表示
  完整顶层替换，可跨越序号缺口，不代表多档盘口补丁。`complete` 必须为真。
- `status`：交易状态、日历修订及明确的常规时段起止；不使用固定 UTC 开收盘时刻。
- `account`：完整余额、现金购买力、外部总持仓及已确认的策略归属和 `cost_basis` 成本金额。正持仓缺成本时关闭新风险门禁。

`meta` 包含 `source_id`、`event_time_ns`、`sequence`。四类输入有各自的递增序号；
报价和状态必须引用当前 `instrument_revision`。输入不接受 JSON 数字作为金额、
价格和数量，也不接受外部提供的接收时间。接收时间由适配器的运行时钟打点。
确定性样本在 `crates/orderhub-gateway/test_data/p4_inputs.json`；其固定历史时间
用于可控时钟测试，其中账户/状态的历史时间不能原样用于当前运行节点。

本入口不向模拟器 REST 查询账户，不把其浮点报价转成权威定点输入，也不自行
生成心跳。外部源的接入与可信时钟依据须在启用该源时独立验证。

## 状态与门禁

- 使用持续推进的 `LiveClock`；测试注入 `VirtualClock` 并显式推进。
- 交易状态/账户最多陈旧 5/10 秒，等于阈值仍有效，超过 1 ns 即阻断。
  报价没有年龄上限；停更、仅报价断连或报价序号缺口不阻断新增风险。
  启动和合约修订变化后仍需至少一条匹配当前定义的合法报价。
  报价不从本地持久化恢复，进程重启后由当前行情源重新补充。
- 源时间和本地接收时间均不能晚于当前时间；本地接收时间不能早于源时间。
  非报价输入的源到接收差值限定在 500 ms 内；报价没有该延迟上限。
- 重复、旧序号和时间倒退的报价不覆盖最后合法值，也不刷新时间；非法报价丢弃。
  较高序号的合法完整报价更新 Cache/Portfolio 并记录缺口。非报价输入异常、未知状态、
  停牌、非授权时段、账户/状态过期和整体输入连接丢失仍阻断新增风险。
- 合约修订改变或定义冲突后，必须重新获得匹配修订的报价与交易状态；未发请求
  在受理与进入原生执行链前按当前定义重新验证，不能沿用旧 tick。
- 外部持仓与策略归属分开存放；不伪造成交或向 Cache 构造原生 Position。
  P5 已完成成交账本、额度预占和持仓归属的同事务持久一致性；外部差异对账仍属 P6。
- 受理前检查能力、整数股、精确 tick、现金购买力、卖出归属和业务截止时间；
  不检查限价相对报价的偏离比例。日志提交后再次检查保留的动态条件，
  失败时记录拒绝并停止进入原生执行链；不复核报价年龄或序号连续性。
- `GetState.writable` 同时考虑生命周期和输入门禁。撤单检查已提交订单归属与当前
  凭证的策略权限，独立于输入门禁；受理撤单意图不代表交易所已完成撤单。
  `writable/stale` 不表示报价实时性。估值沿用最后合法报价并保留真实时间/来源，
  停更期间的估值和敞口可能偏离当前市场。

## P4 验收范围

A01 使用可控时钟验证上述时间、版本、序列、精度、覆盖与故障边界，验证输入更新
进入 Cache/Portfolio、正常请求进入原生风控链，以及 gRPC 拒绝和授权撤单路径。
本阶段不连接 PostgreSQL/Redis，不声明真实行情、真实账户或模拟器订单闭环兼容性；
P5/P6/P8 按主方案继续验收。
