# P5 验收记录

日期：2026-10-02（Asia/Singapore）。结论：**通过本地 profile 范围的 P5 验收**。
范围：当前 Windows 本地 USD 现金权益 profile 的订单、风控、本地持久化与四个 RPC。
主方案见[精简方案](../../../orderhub-project-simplification.md)，实现见
[业务运行时](../../../docs/orderhub/business-runtime.md)，新增阈值见
[P5 阈值及理由](P5-thresholds.md)。P4 输入新鲜度继续沿用 v2。

## 实施结果

- 服务端绑定凭证、提交方及当前策略权限；校验日志代、字段大小、精确数值和通道能力。
  规范化摘要使 `1` 和 `1.00` 表示同一业务值。同键冲突不能覆盖原结果；能力/风险拒绝
  持久返回原 `REJECTED`，不产生订单。拒绝请求不能通过猜测订单 ID 撤单。
- 请求键、原结果、订单、额度/持仓预占、待发送记录、事件及该事件的不可变投影
  在同一 redb Immediate 事务提交。确认前不 ACK、不派发；发送边界先持久化。
  原生 RiskEngine/ExecutionEngine 保留，提交后和实际 FIX 写入前复核动态输入与期限。
- 完整执行事实先持久化再进入原生发布。稳定成交 ID 防止重复结转；同身份经济冲突、
  不支持修正和持久化故障关闭新风险。全量成交优先于迟到撤销，终态仍可接收真实迟到费用。
- 账户/策略预算和市值敞口同时生效；买单精确预占现金与费用，卖单限制已确认归属数量。
  初始正持仓必须有确认成本；部分卖出保守释放成本，全部退出精确释放剩余成本。
  已发送撤单不提前释放占用；已知尚未发送的本地撤销在同一事务释放。
- GetState 增加固定版本快照分页、终态订单及原请求查询。WatchEvents 从签名游标
  连续扫描持久页；每条事件携带该次提交的经济视图，序号/时间/金额不经过浮点 JSON。
  权限过滤账户/策略数据，不向某策略泄露账户全局资金或其他策略归属。
- 新单/撤单/查询分为独立有界队列；限制每提交方在途新单、队列等待、快照租约、
  订阅、FIX 帧和执行回报。慢消费者显式重同步；连接/业务状态变化持久留痕。
  写失败不被忽略；提交未知保留占用并 HALTED。逻辑日志上限留有回报/撤单空间，
  不按年龄删除防重记录。该上限不等于 redb 物理文件大小。
- 本地 FIX 切包修复合并读取多条报文时吞掉中间回报的缺陷，并验证稳定 ExecID。
  协议及真实模拟器运行证据继续按 P6 核销。

## 验收范围与用例

用例是本地组件验证，不依赖 PostgreSQL/Redis 或真实交易所。`p5_api.rs` 直接调用
tonic 服务方法，验证鉴权/状态/事件流语义；它不验证 HTTP/2 传输、TLS 或实际节点进程。
`p5_business.rs` 使用专用 redb 文件及真实 StorageBackend 同步失败注入，没有
测试专用生产开关。原生发布顺序用订阅端断言已提交状态；失败时断言没有发布。

| 主方案编号 | 本阶段证据                                                                                                         | 后续边界                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| A02        | 100 个线程同键仅一订单/预占；规范化重试/冲突；redb 关闭重开后原结果和终态相同。                                    | 真实进程终止/回复丢失在 P6。                                      |
| A03        | 混合事务失败无请求/占用残留；redb 同步失败返回提交未知，保持占用并 HALTED；先持久发送边界；队列过期不受理。        | 提交、回复、发送前后真实杀进程及未知发单对账在 P6；本期不盲重发。 |
| A04        | 部分成交、重复回报、冲突成交、撤单竞争、全量成交后的迟到撤销、原生拒绝、未发送本地撤销。                           | 外部 FIX 闭环和重连覆盖在 P6。                                    |
| A05        | 账户跨策略争用、策略独立预算、单笔数量/价格带、卖出归属减少、精确步进、非法/超大字段和金额。                       | 生产吞吐及通道容量承诺不由此证明。                                |
| A06        | 成本/现金/数量/费用同事务结转；保守成本舍入；迟到费用、费用超缓冲；关闭重开后持仓/资金视图相同。                   | Cache 重建与外部经济差异对账在 P6。                               |
| A13        | 跨提交方撤单/查询/订阅隔离，签名游标篡改和跨身份使用拒绝，账户输入与视图脱敏。                                     | TLS/证书及最终应用配置矩阵在 P8。                                 |
| A14        | 固定 N 分页后补流；事件对应当次提交；16 个租约回收；257 条事件触发慢流重同步；64 新单加 128 查询洪峰保留撤单容量。 | 大数据容量与长期运行承诺后续按部署范围验证。                      |

P4 回归增加正持仓缺少确认成本的门禁，用例数从原验收的 73 增至 74。
共享 `DispatchChannel` 新增有界发送分支；验证满/关队列返回未投递载荷及克隆通道身份。
未扩大到整个 `nautilus-common` 测试集。旧 `m1_grpc.rs`、`m2_local_e2e.rs` 仅编译，
需在 P6 迁移夹具并运行，不将其历史通过记录当作新接口的闭环证据。
