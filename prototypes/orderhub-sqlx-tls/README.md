# SQLx TLS adapter probe

This standalone crate verifies the local SQLx 0.9.0 patch with the pinned stable Rust toolchain.
It installs `rustls-graviola` for one process and uses a local in-process PostgreSQL protocol
fixture. The fixture only handles `SSLRequest` and the TLS handshake; it does not implement a
database. Certificates and keys are test-only fixtures generated by
`../orderhub-no-c-tls/generate-fixtures.ps1`.

```powershell
cargo fmt --manifest-path prototypes/orderhub-sqlx-tls/Cargo.toml -- --check
cargo clippy --offline --locked --manifest-path prototypes/orderhub-sqlx-tls/Cargo.toml --all-targets -- -D warnings
cargo test --offline --locked --manifest-path prototypes/orderhub-sqlx-tls/Cargo.toml --lib
```

The test distinguishes: no installed provider, valid TLS with `VerifyFull`, wrong-host
certificate, server refusal of TLS, and explicit plaintext mode. A valid TLS handshake reaches
the PostgreSQL startup message and then fails because the fixture has no authentication or query
engine. This result is an adapter prototype only, not PostgreSQL integration acceptance.
