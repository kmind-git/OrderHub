# Isolated TLS provider probe

This crate is outside the root workspace. It tests one candidate for the P1 no-third-party-C
path, not an OrderHub application integration or a production TLS approval. The checked-in DER
certificates and PKCS#8 private keys are test-only, self-signed fixtures generated by
`generate-fixtures.ps1`; never deploy them.

Run with the repository's pinned stable toolchain:

```powershell
cargo fmt --manifest-path prototypes/orderhub-no-c-tls/Cargo.toml -- --check
cargo clippy --offline --locked --manifest-path prototypes/orderhub-no-c-tls/Cargo.toml --all-targets -- -D warnings
cargo test --offline --locked --manifest-path prototypes/orderhub-no-c-tls/Cargo.toml
```

The source uses `rustls` 0.23.45 with default features disabled and `rustls-graviola` 0.4.0.
The lock file selects `graviola` 0.4.1. No global provider is installed: client and server
configs each receive the candidate explicitly. The tests execute in-memory TLS 1.2/1.3 handshakes
with ECDSA and RSA certificates and reject wrong-host, untrusted, and expired certificates.
The Windows x64 probe also checks the CPU features required by Graviola before provider use.
The detector reads real CPU features in normal execution; a unit test exercises rejection for
each missing required feature through the same validation function.
They do not test network timeouts, reconnects, client certificates, system roots, Redis,
PostgreSQL, HTTPS, or gRPC.

Graviola includes Rust inline assembly sourced partly from s2n-bignum. Its upstream README calls
the project new and lists required x86-64 CPU features. A successful probe is not a security
review or a guarantee that every deployment CPU supports it.
